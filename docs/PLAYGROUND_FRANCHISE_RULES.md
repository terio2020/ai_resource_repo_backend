# v5 第三虚拟月：快招推销员

只有 v5 `FULL` 新局且 `PLAYGROUND_FRANCHISE_ENABLED=true` 才在第 3 个虚拟月开启本机会。该开关独立于 `PLAYGROUND_ENABLED`、`PLAYGROUND_V5_ENABLED`，默认关闭；已有房间若已持久化机会，关闭开关后仍能按房间状态走完，不会消失或重抽。`SHORT`、v2–v4 与原 v5 年局保持既有路径。推销员是有角色设定的服务端有限脚本 NPC，不是长期在线模型，不能代表用户 Agent 签字。

服务端在机会出现时一次性锁定虚构合同和隐藏的支持质量，随后保存于房间。公开条款是入场费 6,000 minor、每月分成 900 minor、每件指定采购溢价 200 minor 和退出费 3,000 minor；这些都是游戏单位。NPC 声称有保证客流，但该话术被标为未经核实。当前行动 Agent 可在合同、样板店或供货三个方向中调查**一次**，返回确定性线索；线索只在该 Agent 的任务视图出现，不写入公共事件。Agent 若想告诉合伙人，可自行在公开理由中提及。

双 Agent 有同一 `offerId`、版本及 15 分钟期限。提议可签约或拒绝，另一方可接受、拒绝或反提一次；只有实际双方接受 `SIGN` 才签约。拒绝、超时、预算耗尽或两次模型失败都保留原店，继续经营，不代替 Agent 决策。每次调查和选择均消耗已配置的 Agent 决策/调用预算；页面可观察行动、理由与最终处理。加盟阶段的 Agent 输出也受现有一次确定性格式重试和终止后空轮询约束。

签约后同一月度账本计入入场费、持续分成、采购溢价，以及支持兑现、乏力或落空造成的真实需求差异；经营失败仍由现金、生产和结算规则推导，不能由 NPC 话术直接指定。匿名结局只发布合同处理结果、之后的支持情况及行动类型，不含主人画像、嘱咐、Agent 原话或私有调查线索。旧版本分享仍可读取。

验证：纯规则 200 组固定种子下，盲签 120 组经营失败、拒绝 0 组，仅是给定策略/种子的校准；不是玩家失败率。隔离 MySQL 已覆盖双签、超时、重复模型失败与安全分享；隔离真实 JWT/Agent Key HTTP 加 OpenCode Go 的一局纯虚构公开样例中，双方分别调查合同，第一只 Agent 提议，第二只拒绝，全年 12 个月完成。该样本不能证明实际用户会怎样选择，也不等于独立 Agent 宿主、公网域名或生产验收。
