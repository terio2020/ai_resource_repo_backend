# Playground v5 房间与规则

v5 在 `PLAYGROUND_ENABLED`、`PLAYGROUND_V5_ENABLED` 打开时创建 2 或 12 个虚拟月的合伙小店。快招推销员另受 `PLAYGROUND_FRANCHISE_ENABLED` 控制。开关的配置默认值仍是 `false`；生产环境的实际值由部署配置决定。既有 v2–v4 房间继续使用原规则。

双方 Agent 必须同意同一份包含店名、经营内容、目标顾客、体验、营销方案、产量、售价、预留现金和受控策略的提案。商品或可重复交付的本地服务都可成为一个“标准单位”。目标客群包括夜读者、通勤者、学生、邻里、家庭、养宠人和兴趣爱好者。自然语言只形成公开承诺，不直接修改服务端收入、成本或购买力。`V5StrategyContract` 严格解析枚举和预算。

新建 v5 房间采用规则 `0.8`。服务端在签约时持久化一个非负客流种子；每月根据种子和虚拟月份计算可复算的冷清、平稳或热闹客流。全年必有一次第 4–6 月的高峰和一次第 9–11 月的低谷，其余月份随种子变化。客流影响实际成交，售价、库存与营销仍决定能否接住需求；固定成本和备货支出持续发生，剩余库存按原规则在结局时折价清算。月报用事件码记录客流变化，公开页面只能展示账本中的真实结果。规则 `0.6`、`0.7` 的存量房间保持原算法和事件时点，不因部署新代码重新结算。

全年局在第 2 月遇到竞争者、第 5 月遇到供应商断货，并在服务端预先抽定的第 7–9 月遭遇一次市场、材料、租金、包装或停电冲击。每次事件都开启双 Agent 的有限协商：维持定位、加大宣传或当月临时调整。供应商断货使当月可生产量少 2 单位，每单位增加 200 minor 成本，并流失 1 位潜在顾客；临时调整可补回 1 单位，但需承担相应调整成本及临时售价。选择进入真实账本，事件与应对在月报和分享中可追溯。超时、预算不足或确定性模型失败都记录原因并按已签方案结算。

全年局开店前先遭遇快招推销员，两只 Agent 可调查和协商是否加盟，然后再提出具体创业项目与经营方案；签约费用从开业第 1 月开始。脚本竞争者和环境事件由服务端生成，不冒充真人或模型 NPC。短局没有快招与第 5 月事件。

金币是虚拟游戏单位，不是实际货币、真实市场预测或投资建议。账本记录月初/月末现金、销售、进货、费用、库存、清算及累计盈亏；月报满足现金和利润守恒。发布新规则时应先在预发布运行真实模型同局验收，再切换生产后端、前端与 Agent 合同，核对旧公开结局及新结局。Flyway 回退可能删除 Playground 数据或改变下架标记，回退前须备份并停用入口。
